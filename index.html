03 / MATHEMATICAL FOUNDATIONS

What it really means.

The same group-law idea extends to cryptographic curves — but the security claims do not transfer to this tiny example.

01

The toy curve

Our points satisfy y² ≡ x³ + 7 (mod 17). We work with integer coordinates from 0 to 16, using arithmetic modulo 17, plus the identity element 𝒪 (point at infinity). There are 17 finite points and 18 group elements in total.

02

Point addition

For distinct P = (x₁,y₁) and R = (x₂,y₂), the slope is λ = (y₂ − y₁) · (x₂ − x₁)⁻¹ mod 17. For doubling P, λ = 3x₁² · (2y₁)⁻¹ mod 17. Then x₃ = λ² − x₁ − x₂ and y₃ = λ(x₁ − x₃) − y₁, both modulo 17. The inverse is modular, not ordinary division.

03

Identity & finite order

𝒪 + P = P; P + (−P) = 𝒪, where −(x,y) = (x,−y mod 17). Every point has finite order. In the default example, 9G = 𝒪, so 10G = G: scalar multiplication repeats.

04

Connection to Ethereum

Ethereum uses secp256k1: y² ≡ x³ + 7 over a vastly larger prime field. A private scalar k generates a public point Q = kG. Ethereum addresses are then derived from an encoded public key using Keccak-256; the point Q itself is not the Ethereum address.

INTERPRETING THE RESULTS

One-way function ≠ hash function

KEY DISTINCTION
Relevant to scalar multiplication

Deterministic forward operation. The same k and G always give the same Q. For a real, appropriately chosen large-order elliptic-curve group, computing kG is efficient while recovering k from Q is believed computationally infeasible (ECDLP).

Group structure matters. Scalars repeat modulo the order of G, and scalar multiplication obeys (a+b)G = aG+bG. This algebraic relationship explains why simple input-output plots cannot establish security.

Hash-specific expectations

Avalanche behavior. Cryptographic hash functions are designed so a tiny input change typically changes roughly half the output bits. This is not a required property of elliptic-curve point multiplication; chosen point encodings and coordinate representations matter.

Uniformity and collision resistance. The output points are uniformly distributed over the subgroup if k is sampled uniformly modulo its order. Their coordinates and individual bits need not be uniform. Hash collision/preimage properties are different security goals.

Why this toy is insecure: only a handful of scalar possibilities exist. An attacker can compute every kG and recover a matching scalar by a trivial lookup. Any correlation, bit-balance or apparent randomness found here is descriptive, not evidence of cryptographic strength.
CONCLUSION

Scalar multiplication creates a public point from a secret scalar by repeated group addition. The hardness of reversing that map on suitable large groups — not the visual randomness of coordinate histograms — is the central idea of elliptic-curve public-key cryptography.
