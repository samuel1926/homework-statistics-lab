01 / FOUNDATIONS

Two ciphers. Two very different assumptions.

Both algorithms transform information, but they do not achieve the same security properties. This distinction is essential before investigating an attack.

A→D

Caesar cipher

Classical · symmetric · deterministic

Each alphabetic character is rotated by a secret integer k ∈ {0,…,25}. Encryption preserves punctuation, letter case, and the frequency distribution up to a permutation of letter labels.

Ek(p) = (p + k) mod 26
Dk(c) = (c − k) mod 26
A Caesar ciphertext has exactly the same letter entropy as its plaintext, because a fixed rotation simply relabels characters.
G

Elliptic-curve scheme

Public-key · randomized · educational

On the actual secp256k1 curve, Bob's secret scalar d defines a public point Q=dG. Alice selects a fresh ephemeral scalar r and obtains the same ECDH point as Bob.

SA = rQ = rdG = d(rG) = SB
We derive SHA-256 blocks from the shared point and XOR them with plaintext bytes. This is a nonstandard teaching construction, not production ECIES/AEAD.

THE ESTIMATOR
χ²(k) = Σi=AZ (Oi(k) − Npi)² / (Npi)

Here Oᵢ(k) is the count of letter i after decrypting with candidate shift k, N is ciphertext letter count, and pᵢ is the estimated reference probability from the training corpus. Compute the statistic for each key and take argminₖ χ²(k).

This is a goodness-of-fit ranking heuristic: assumptions for a formal chi-square test (notably adequate expected counts and independent observations) do not hold exactly for letters in natural language, especially in short texts. We use the statistic as a score, not as a hypothesis-test p-value.

Interpret the observed results

After running the benchmark, a summary based on the actual collected results will appear here. We intentionally do not invent an accuracy percentage in advance.

What should happen theoretically?

For a distinctive known-language letter distribution, estimates of frequencies generally stabilize as the number of observations increases. A correct key should tend to align with the reference distribution, whereas most incorrect rotations should disagree. Finite samples, topic differences, and atypical writing can overturn this expectation.

Three estimators, different information

01
Chi-square fit

Uses all 26 unigram counts; low distance indicates a plausible candidate.

02
N-gram log-likelihood

Uses adjacent letter pairs and triples. Can exploit word-like order when single-letter frequencies are ambiguous.

03
Most-frequent-letter heuristic

Aligns the largest ciphertext peak with the largest reference peak. Fast, but often unreliable.

All three enumerate the same 26 shifts. 'Exhaustive search' alone produces candidate plaintexts; an automatic attack also needs a rule to rank them.

Why a 256-bit keyspace changes everything

Generic ECDLP algorithms on a prime-order subgroup take roughly the square root of the group size, unlike a linear enumeration of every private key.

For real secp256k1, the private scalar is chosen uniformly from 1,…,n−1 with a subgroup order close to 2²⁵⁶. Pollard's rho needs approximately O(√n)≈2¹²⁸ group operations in the generic model. This is infeasible at plausible computing scales; the classroom attack only works because B≪n.

06 / MATHEMATICAL DEMONSTRATIONS

The reasoning behind every experiment.

Step-by-step derivations connecting the code, the attacks, and the interpretation of the results.

PROOF 01

Correctness of the Caesar cipher

Encode letters as residue classes in ℤ₂₆. For any plaintext letter p and key k:

Dk(Ek(p)) = ((p+k)−k) mod 26
= p mod 26 = p

Because addition by k is a bijection, no letter is lost. The same shift applies to every occurrence, however, making substitutions statistically visible.

PROOF 02

Statistical leakage: rotation and entropy invariance

Let pᵢ denote the empirical fraction of plaintext letter i, and let ciphertext letter j have frequency qⱼ. Under a Caesar shift k, qⱼ=p(j−k) mod 26. This is only a permutation of the same 26 numbers.

H(C) = −Σj qjlog₂qj
= −Σi pilog₂pi = H(P)

The index of coincidence IoC = Σᵢ nᵢ(nᵢ−1)/(N(N−1)) is likewise invariant under a fixed letter permutation. It can identify monoalphabetic-language-like frequency concentrations, but cannot by itself distinguish Caesar's 26 rotations.

PROOF 03

Why the frequency estimator improves with more text

For an idealized independent sample from a known letter distribution, the empirical probability of a letter converges to its true probability. In particular, for a letter with probability p:

E[p̂] = p,   Var(p̂) = p(1−p)/N
SD(p̂) = √(p(1−p)/N)

The estimation error thus scales like 1/√N. If the population distributions corresponding to candidate rotations differ, a sufficiently long independent sample favors the correct alignment.

Natural-language letters are not independent and the estimated reference distribution is imperfect. A domain mismatch, short input, nonstandard language, or deliberately unusual text can cause failures even when the formula is applied correctly.

PROOF 04

Correctness of elliptic-curve decryption

Bob's public point is Q=dG. Alice chooses ephemeral r, sends R=rG, and computes S=rQ. Bob obtains:

dR = d(rG) = (dr)G = r(dG) = rQ = S

Because both sides recover the same curve point, they can independently derive the same byte mask M. Encryption uses C=P⊕M; decryption uses C⊕M=(P⊕M)⊕M=P. A fresh ephemeral scalar changes the mask across encryptions.

The demonstration validates received points but is still nonstandard and has no authentication tag. Flipping ciphertext bits flips corresponding plaintext bits, so the design is malleable and must not be used to protect real data.

PROOF 05

Bounded ECDLP search and baby-step giant-step

We know Q=dG with 1≤d≤B. Sequential exhaustive search computes G,2G,3G,…,BG and compares each with Q. The running time is O(B) curve additions with constant auxiliary memory.

For baby-step giant-step, choose m=⌈√(B+1)⌉. Write the unknown scalar as d=jm+i, where 0≤i<m. Then:

Q = (jm+i)G
Q − jmG = iG

Precompute and hash baby steps iG; compare them against giant steps Q−jmG. The match gives d=jm+i, subsequently validated against the bound and public key. Complexity is O(√B) time and O(√B) storage. These are restricted-interval attacks; with a full 256-bit order, generic square-root attacks still require approximately 2¹²⁸ operations.

PROOF 06

Uncertainty of Monte Carlo success rates

At a fixed sample length, suppose the estimated key is correct in s out of T trials. The measured success fraction is p̂=s/T. We show a two-sided 95% Wilson interval rather than reporting the fraction alone.

CI = [ (p̂+z²/(2T)) ± z√(p̂(1−p̂)/T+z²/(4T²)) ] / (1+z²/T)
with z = 1.96

The interval expresses statistical uncertainty for a binomial-style experiment under the specific sampling model. It does not establish robustness for every language, every document, or highly correlated overlapping samples. Independent source documents would provide stronger external validity.

07 / INTERPRETATION & FINAL CONCLUSIONS

What the experiments establish — and what they do not.

Security depends on both mathematics and implementation. The weakest assumption, not the most impressive formula, can determine the outcome.

01

Caesar is statistically transparent.

A letter rotation preserves monogram frequencies and empirical entropy. Even without a language corpus, the entire 26-element keyspace is trivially enumerable. With a known-language corpus, chi-square and n-grams provide a practical automated selection rule.

STRUCTURAL LEAKAGE + TINY KEYSPACE
02

Length controls the amount of evidence.

Longer ciphertexts generally provide more stable frequency estimates. However, success is not a mathematical certainty for any particular finite text. The benchmark tests the trend empirically and reports uncertainty, instead of treating one successful decryption as proof.

MEASURED, NOT ASSUMED
03

ECC fails here because we weakened its keys.

Restricting d to a small interval makes the discrete logarithm searchable. This does not imply that secp256k1 itself is broken: uniformly sampled full-range keys provide roughly 128-bit generic discrete-log security in the classical computational model.

PARAMETER-CHOICE WEAKNESS
04

A correct curve does not rescue an unsafe protocol.

The lab's XOR construction has no message-authentication mechanism and is malleable. A real system must use established protocols, authenticated encryption, point validation, high-entropy randomness, and careful key handling. Statistical flatness alone is never sufficient evidence of security.

DESIGN AND IMPLEMENTATION MATTER
FINAL SYNTHESIS

Different attacks exploit different information.

For Caesar, the attacker exploits redundancy in natural language and a tiny set of possible shifts. For restricted-key ECC, the attacker exploits an artificially constrained private-scalar interval and the public relation Q=dG. The first attack is informed by the statistical shape of plaintext; the second does not need plaintext statistics at all.

When used with standard algorithms and a full-strength keyspace, elliptic-curve cryptography resists known generic classical discrete-log attacks at practical scales. But this educational ECDH-plus-XOR construction should never be represented as production-secure encryption.
